**ЯЗЫК: всё общение с дизайнером — по-русски, простыми словами.** Никакого
техножаргона и английских названий шагов в том, что видит дизайнер.

Ты собираешь не Figma-макет, а самодостаточный HTML-файл (или несколько), который
можно открыть двойным кликом в любом браузере и покликать. Стиль — тот же кит
(токены, раскладка, паттерны), просто другой формат вывода. Макет в Figma при этом
не трогаешь и не заменяешь — это отдельный, параллельный результат.

Вход: $ARGUMENTS

Если строка выше пустая — спроси у дизайнера одной строкой: «Опиши экран или
короткий сценарий, который нужно собрать прототипом — словами, как обычно».

## Шаг 0. Загляни в кит, как и при рисовании в Figma

Молча, прежде чем писать HTML:
- [`ux-lab/best-practices/INDEX.md`](../../../ux-lab/best-practices/INDEX.md) — вдруг паттерн уже есть;
- [`ux-lab/foundation/layout.md`](../../../ux-lab/foundation/layout.md) — раскладка-«острова» (рейл 64 + шапка 56 + [сайдменю 320] + центр + [правая панель 360]);
- [`ux-lab/foundation/templates/INDEX.md`](../../../ux-lab/foundation/templates/INDEX.md) — определи тип экрана (Create/Notification/Sidemenu/SidePage/Filters) и открой карточку нужного шаблона;
- [`ux-lab/foundation/components/INDEX.md`](../../../ux-lab/foundation/components/INDEX.md) — открывай карточки конкретных компонентов, которые нужны на этом экране (кнопки, инпуты, таблица и т. п.), по мере надобности, не все сразу.

Подходящего шаблона нет — скажи об этом дизайнеру и собери по ближайшему, не выдумывай раскладку с нуля (то же правило, что и в Figma-режиме).

## Шаг 1. Токены — всегда из готового файла, не выдумывай HEX/px

Открой [`ux-lab/foundation/tokens/tn-life.css`](../../../ux-lab/foundation/tokens/tn-life.css) — это уже готовый CSS с
переменными (`--content-*`, `--background-*`, `--border-*`, `--space-*`,
`--radius-*`, шрифтовые токены и именованные текстовые стили `.text-*`),
собранный из [`tokens.md`](../../../ux-lab/foundation/tokens.md). Значений там уже достаточно — **не
дописывай новые цвета/отступы на глаз**, если нужного токена нет — так и скажи
дизайнеру, не подменяй догадкой (то же правило №1 из корневого README кита).

Файл целиком копируется внутрь `<style>` каждого прототипа (прототип должен быть
самодостаточным, без внешних ссылок на .css) — не сокращай и не пересказывай его
своими словами, бери как есть.

## Шаг 2. Собери HTML на раскладке кита

- Разметка — на структуре из `layout.md`: рейл слева (64), шапка (56), рабочие
  зоны как отдельные «острова» со скруглением (`--radius-*`) и зазорами
  (`--space-*`) между собой и от краёв страницы — не приклеивай блоки к краям.
- Компоненты собирай по правилам из карточек `foundation/components/*.md` —
  состояния (`default/hover/focus/active/disabled/loading/error`) реализуй
  через CSS (`:hover`, `:focus-visible`, классы `.is-loading`/`.is-error` и т. п.),
  а не только описывай.
- Продумай пустое/загрузка/ошибка состояния экрана — как минимум упомяни, что для
  них предусмотрено (визуально или отдельным блоком за display:none, который
  можно показать переключив класс).
- Интерактивность — минимальный vanilla JS без сборки и без внешних библиотек
  (клики, простые переходы между экранами, открытие/закрытие панелей). Ничего не
  подключай из интернета (ни шрифты, ни иконки, ни JS-библиотеки) — прототип
  должен открываться офлайн одним файлом.
- Иконки — инлайновый SVG (простые формы) или текстовые заглушки, раз внешних
  иконных шрифтов подключать нельзя.

## Шаг 3. Один экран или флоу — выбери формат по сложности задачи

- **Один экран** → один файл `index.html`.
- **Короткий флоу (2–4 экрана)** → один файл с несколькими `<section data-screen="...">`
  и простым JS-переключателем по клику на кнопки перехода — это удобнее открывать
  и пересылать, чем несколько файлов.
- **Длинный флоу или явно разные разделы** → отдельные `.html` файлы со ссылками
  друг на друга (`<a href="second.html">`), если единый файл станет нечитаемым.

Не выдумывай экраны, которых дизайнер не просил — только то, что явно в задаче.

## Шаг 4. Сохранение

Сохраняй в `prototypes/<короткое-название-задачи>/` в корне репозитория:
`prototypes/<название>/index.html` (+ доп. файлы, если флоу разбит на несколько
страниц). Короткое название — латиницей, kebab-case, по смыслу задачи.

## Шаг 5. Покажи результат

Дизайнеру не нужен код — покажи только:
- одну строку, что собрал;
- путь к файлу и как открыть («открой `prototypes/<название>/index.html`
  двойным кликом в браузере»);
- если делал несколько состояний/экранов — как между ними переключаться.

Спроси, что поправить — правишь по тем же правилам кита, что и в Figma-режиме.

## Инварианты

- Дизайн-система у нас есть всегда — не говори «нет токенов» и не собирай стиль
  с нуля, раз `tn-life.css` уже готов.
- Не переписывай значения токенов вручную внутри HTML — только через переменные
  из `tn-life.css`.
- Прототип — не замена Figma-макета и не оркестр; если дизайнер после прототипа
  захочет тот же экран в Figma — это отдельная задача (пункт 1 или 2 главного меню).
- Сработал триггер Правила №2 кита (неочевидное решение, ограничение платформы,
  грабли) — предложи паттерн тем же способом, что и в Figma-режиме.
