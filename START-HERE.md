# 🟢 START HERE — инструкция для новичка

Ты открыл этот репозиторий, чтобы **рисовать макеты в Figma с помощью Claude**.
Ниже — всё по шагам, максимально просто. Читать 3 минуты.

---

## Что это вообще такое

Это **не программа**, а **набор знаний + помощник**. Claude (ИИ) читает правила
из этой папки и рисует за тебя экраны прямо в Figma, в едином стиле компании.

Твоя работа сводится к одному: **написать задачу словами**. Всё остальное делает Claude.

---

## Два режима — выбери под ситуацию

Когда ты попросишь нарисовать макет, Claude сам спросит:
**«⚡ быстро или 🎼 оркестр?»**. Вот в чём разница.

### ⚡ Быстрый режим — бери его почти всегда
- **Что это:** ты пишешь «сделай экран X» — Claude сразу рисует в Figma.
- **Зачем нужен:** быстро проверить идею, набросать один-два экрана, поправить компонент.
- **Кому:** одиночная работа, джуны, черновики.
- **Минусы:** нет строгих проверок — это «быстрый набросок по правилам кита».

### 🎼 Режим оркестра — для серьёзных фич
- **Что это:** конвейер из нескольких ИИ-агентов. Один разбирает задачу, другой
  сверяет с дизайн-системой, третий принимает решения со ссылками на правила,
  четвёртый рисует, пятый ведёт историю. По пути — **паузы (гейты)**, где ты
  подтверждаешь решения.
- **Зачем нужен:** когда важно, чтобы всё было строго по стандарту, с обоснованием
  каждого решения, и чтобы результат был предсказуем в большой команде.
- **Кому:** сложные фичи, командная работа, то, что пойдёт в продакшн.
- **Минусы:** дольше, задаёт больше вопросов, требует установки агентов (Claude
  ставит их сам при первом запуске).

> Не знаешь, что выбрать — бери **⚡ быстрый**. Оркестр включишь, когда почувствуешь,
> что задача большая и её надо делать «по-взрослому».

## Что нужно один раз (обязательно)

1. **Подключить Figma** к Claude: Settings (⚙️) → Connectors → **Figma** → Connect.
2. **Открыть в Figma** тот файл, куда рисовать. Claude рисует в **активную вкладку** —
   то есть в тот файл Figma, что у тебя сейчас открыт.

Больше ничего настраивать не надо. Ссылки, токены, стиль — уже прописаны в ките.

---

## Как открыть и пользоваться — 3 способа

Выбирай тот, что тебе привычнее. Дальше всё одинаково: **пишешь задачу словами**.

### Способ A. Claude Code в терминале (CLI)
1. Склонируй репозиторий и зайди в папку:
   ```bash
   git clone https://github.com/Lavuix/UX-UI-skills.git
   cd UX-UI-skills
   ```
2. Запусти Claude:
   ```bash
   claude
   ```
3. Напиши задачу, например: `сделай экран заказа справки`.
4. Claude спросит режим → ответь `быстро` или `оркестр` → смотри, как рисует в Figma.

### Способ B. Настольное приложение Claude (Mac/Windows)
1. Открой приложение **Claude**.
2. Слева выбери/добавь папку проекта — склонированный `UX-UI-skills`
   (кнопка открытия папки / «New session» с этой папкой).
3. Убедись, что вверху написано имя папки `UX-UI-skills`.
4. В поле ввода напиши задачу словами → ответь на вопрос про режим → готово.

### Способ C. VS Code (расширение Claude Code)
1. **File → Open Folder →** выбери склонированный `UX-UI-skills`.
2. Открой панель **Claude** справа (иконка Claude на боковой панели).
3. В поле «Describe what to build» напиши задачу словами.
4. Ответь на вопрос про режим → смотри результат в Figma.

> Во всех трёх способах Claude автоматически читает правила из `CLAUDE.md` этого
> репозитория — поэтому и знает, что спросить и как рисовать.

## Как выглядит работа (пример)

```
Ты:     сделай экран заказа справки с места работы
Claude: Как рисуем — ⚡ быстро или 🎼 оркестр?
Ты:     быстро
Claude: [заглядывает в правила кита и токены]
        [рисует экран в твоей активной вкладке Figma]
        Готово. Вот скриншот. Что поправить?
```

Дальше просто говоришь, что изменить: «сделай кнопку синей», «добавь пустое
состояние», «покажи ошибку» — Claude правит прямо в Figma.

## 💡 Нашёл полезное решение? Отправь Антону в библиотеку практик

Иногда в ходе работы всплывает **неочевидное решение** или **грабли, о которых
стоит помнить** (долго возились, нашли трюк, ограничение Figma и т.п.).

Claude сам это замечает и предлагает оформить **паттерн (best practice)**:
1. Claude формулирует урок и оформляет его по шаблону
   `ux-lab/best-practices/patterns/_TEMPLATE.md`.
2. Показывает тебе готовый текст паттерна.
3. Говорит: **«Отправь это Антону, чтобы он добавил в библиотеку практик кита.»**

Тебе не надо самому коммитить в кит — просто **перешли этот текст Антону**
(в мессенджер / задачу). Он проверит и добавит в общую библиотеку, чтобы урок
стал доступен всей команде. Так кит становится умнее с каждым проектом.

> Почему через Антона: библиотека практик — общая и версионируется вручную,
> чтобы туда попадало только проверенное. Джуну достаточно принести находку.

## Если что-то не так

- **Claude не рисует в Figma** → проверь: подключён ли Figma-коннектор и открыт ли
  файл в Figma (активная вкладка).
- **Claude сразу начал делать, не спросив режим** → просто скажи «стоп, хочу оркестр»
  или «давай быстро».
- **Хочешь заново** → напиши «начнём заново» — Claude сбросит и переспросит.

Всё общение — по-русски. Не бойся ошибиться: можно в любой момент сказать
«отмени» или «переделай».
