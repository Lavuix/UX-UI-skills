# UX Lab — процесс hypothesis-driven design

Система, в которой каждый макет рождается из проверяемой гипотезы, проходит
проверку по UX-практикам, а подтверждённые выводы копятся в базу лучших практик
и переиспользуются в следующих задачах.

## Цикл

```
  ┌─────────────┐     ┌──────────────┐     ┌───────────────┐     ┌────────────────┐
  │ 1. Гипотеза │ ──▶ │ 2. Макет под │ ──▶ │ 3. Проверка   │ ──▶ │ 4. Лучшая      │
  │             │     │    гипотезу  │     │   по практикам│     │    практика    │
  │ hypothesis  │     │   (Figma)    │     │ критика / a11y│     │ best-practices │
  │  .md        │     │              │     │ копирайт / DS │     │                │
  └─────────────┘     └──────────────┘     └───────────────┘     └───────┬────────┘
        ▲                                                                 │
        └───────────────── переиспользуем при новой задаче ◀─────────────┘
```

Ключевая идея: **перед началом любого нового макета сначала смотрим в
`best-practices/INDEX.md`** — возможно, нужное решение уже проверено и не надо
изобретать заново. Это и есть «память»: не хранить всё в голове, а вытаскивать из
базы.

```

│   ├── 4-testing.md                 ← как запускать тесты
│   ├── 5-designing.md               ← как рисовать / собирать
│   └── 6-style-from-mockups.md      ← где брать стиль из макетов
├── rules/                           ← свод правил UI/UX
│   ├── README.md                    ← индекс + Definition of Done
│   ├── 01-cognitive-laws.md         ├── 04-visual-hierarchy.md
│   ├── 02-gestalt.md                ├── 05-accessibility.md
│   └── 03-nielsen-heuristics.md     └── 06-forms-content-interaction.md
├── foundation/
│   └── tokens.md                    ← реальные токены, извлечённые из Figma
├── templates/
│   └── hypothesis.md                ← шаблон гипотезы (копируй под каждую новую)
├── hypotheses/
│   └── H-000-EXAMPLE.md             ← пример заполненной гипотезы
├── best-practices/
│   ├── INDEX.md                     ← быстрый индекс (хот-кэш) всех проверенных паттернов
│   └── patterns/

│       └── EXAMPLE-forms.md         ← пример заполненного паттерна
```

Спеки для оркестра лежат отдельно, в `specs/` в корне проекта (вход для `/feature`).

Двухуровневая память по аналогии с рабочим кэшем:
- **`INDEX.md`** — одна строка на паттерн, для быстрого просмотра «что у нас уже есть».
- **`patterns/*.md`** — подробная запись с доказательствами, когда паттерн нужен в работе.

## Как пользоваться

**Новая задача:**
1. Открой `best-practices/INDEX.md` — есть ли готовый проверенный паттерн?
2. Если нет — заведи гипотезу: скопируй `templates/hypothesis.md` в `hypotheses/`
   с именем `H-XXX-короткое-название.md`.
3. Собери макет в Figma именно под проверку этой гипотезы.
4. Прогони по практикам (см. ниже) и проверь выбранным методом.
5. Если подтвердилась — вынеси вывод в `best-practices/patterns/` и добавь строку
   в `INDEX.md`.

**Есть готовый макет и нужно только проверить его на пользователях** (без сборки
фичи) — режим Исследователь (`/research`, пункт 5): картинка или ссылка на Figma →
подбор персон из `research/personas/` → синтетический прогон → отчёт в
`research/reports/`. См. `.claude/skills/research/SKILL.md` и `4-testing.md`.

**Проверка по практикам** (шаг 3) — прогоняем макет через:
- дизайн-критику (иерархия, консистентность, юзабилити),
- доступность (контраст, клавиатура, размеры целей — WCAG 2.1 AA),
- UX-копирайт (кнопки, ошибки, пустые состояния),
- консистентность с дизайн-системой (токены, компоненты).

## Методы проверки гипотез

| Метод | Для чего | Выборка | Срок |
|-------|----------|---------|------|
| Интервью | Глубина: потребности и мотивация | 5–8 | 2–4 нед |
| Юзабилити-тест | Оценка конкретного макета/потока | 5–8 | 1–2 нед |
| Опрос | Количественная оценка отношения | 100+ | 1–2 нед |
| Card sorting | Решения по информационной архитектуре | 15–30 | 1 нед |
| A/B-тест | Сравнение конкретных вариантов | до значимости | 1–4 нед |

## Уровни уверенности

Каждый паттерн в базе помечается уровнем — насколько ему можно доверять:

- 🟢 **Подтверждено данными** — A/B-тест, метрики в проде.
- 🟡 **Подтверждено тестами / эвристикой** — юзабилити-тесты, экспертная оценка.
- ⚪ **Допущение** — ещё не проверено, держим в базе как кандидата.
