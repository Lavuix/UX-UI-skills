# 6. Где брать стиль — из макетов

Стиль не выдумываем: вытаскиваем из существующего Figma-файла и фиксируем в
`foundation/tokens.md`. Дальше макеты собираются из этих токенов, а не из
случайных значений.

## Метод (через Figma MCP)

1. **Дай ссылку на конкретный фрейм** — URL с `node-id`, например
   `.../design/<fileKey>/...?node-id=1-4737`. Без node-id инструменты не знают,
   какой узел смотреть.
2. **Структура** — `get_metadata` по узлу: layout, размеры, вложенность, имена
   компонентов. Отсюда — ритм и сетка (паддинги, высоты строк).
3. **Внешний вид** — `get_screenshot` (инлайн-картинкой), чтобы увидеть экран и
   оценить визуально.
4. **Токены** — `get_variable_defs` по узлу: реальные переменные (цвета, шрифты,
   размеры, радиусы). Это главный источник — копируем в `foundation/tokens.md`.
5. **Компоненты** — `get_design_context` по конкретному компоненту (кнопка,
   строка, статус), если нужны точные значения отдельного элемента.

## Что фиксируем в foundation

- Палитра: content / background / border / статусы — с токен-именами и HEX.
- Типографика: семейство, размеры/интерлиньяж, начертания, веса.
- Радиусы, паддинги, высоты, сетка.
- Замечания к системе (коллизии токенов, провалы контраста).

## Пример (уже сделан)

Из файла «Корпоративный помощник» (node 1:4737) извлечены реальные токены →
`foundation/tokens.md`. Там же зафиксированы два флага: бренд-красный совпадает с
красным ошибки, и `content/tertiary` не проходит по контрасту. Это и есть связка
«взять стиль → сразу проверить его по правилам».

## Важно

- Токены из файла — **источник правды**. Если в макете значение «мимо токена» —
  это баг консистентности, а не новый стиль.
- Библиотека компонентов должна быть **опубликована** (Assets → Publish) и
  включена в рабочем файле — иначе Scout/Builder оркестра «не видят» её.
- `get_variable_defs` работает от выбранного узла; держи нужный фрейм выделенным
  в десктоп-Figma, если запрос просит selection.
