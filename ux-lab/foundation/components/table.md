## Назначение

Табличное представление данных: список строк с настраиваемыми колонками,
групповые операции над выбранными строками, десктопные скролл/пагинация,
корнер-кейсы загрузки и древовидная (вложенная) разновидность.

## Из чего собрана

Table — не один вариант-компонент, а организм из собственных строительных
блоков + переиспользованных атомов кита. Ничего не скопировано из
макетов-образцов — см. [`source-components-from-kit-only.md`](../../best-practices/patterns/source-components-from-kit-only.md).

**Собственные компоненты (живут на странице «Table»):**
- **Connector (Frame 1948759195)** — коннектор древовидной линии, State =
  Default/Variant2 (продолжается / последний потомок), 16×24, привязан к
  `border/secondary/enabled`. Ставится в начало ячейки «Название»/«Материал»
  вместо чекбокса-заглушки, перед шевроном.
- **Table Cell** — компонент-сет со слотом (`Content`), Size = S/M × State =
  Enabled/Hovered/Pressed. Слот один на размер (S и M делят контент между
  своими тремя состояниями) — см.
  [`slot-cell-variant-states.md`](../../best-practices/patterns/slot-cell-variant-states.md)
  про грабли с этим на будущее. Слот-фрейм — **без своего фона**
  (`fills: []`), иначе перекрывает hover/pressed-цвет самой ячейки.
- **Group Actions Bar** — тёмная плавающая панель массовых действий
  (`background/primary-b/enabled`), появляется при выделении строк. Чекбокс +
  счётчик + слот с Action Button'ами + кнопка «Ещё» (с дропдауном, раскрывается
  вверх — панель обычно у низа таблицы).

**Переиспользованные атомы кита (как есть, без правок токенов):**
CheckboxSquare, Tag, Userpic, Action Button, Pagination (`.Page` +
`Chevron/M/Left`/`Chevron/M/Right` из готовой строки `Pages`), Scroll,
Empty Content (для ошибки загрузки), иконки Life-10_Icons **только Light**
(Settings, Sort, Chevron/M/Down, Down, Up — см.
[`icon-family-outline-light.md`](../../best-practices/patterns/icon-family-outline-light.md)).

**Статусные цвета:** точки этапа, дельта (план/факт) — только семантические
`content/system/positive` · `content/system/negative` · `content/system/warning`
· `content/action` (Theme_Light). **Не примитивы бренда напрямую** (`Green/50`,
`Orange/55`, `Blue/50` и т.п.) — так и было по ошибке сначала, tokens.md прямо
запрещает: «⛔ Напрямую не использовать» про Brand-палитру. Отступы/радиусы/цвета
у **всех** новых узлов Table — через `setBoundVariable`/`setBoundVariableForPaint`
на реальные переменные кита, никаких чисел и hex руками — тот же принцип, что и
у типографики ниже.

**Типографика:** только стили из Life-02_Font, не ручной fontName/fontSize —
`Body/body-small-*` (13px) для текста ячеек и заголовков колонок,
`Label/label-medium-*` (11px) для мелких подписей (слот-плейсхолдер, %,
агрегат-бейджи). `-hard` = Medium (акцент), `-light` = Regular.

## Типы ячеек

Слот `Table Cell` принимает любой контент — на странице описаны образцы:
текст, дата, Tag (статус/приоритет), Userpic+имя (исполнитель), редактируемое
поле (текст placeholder + `Chevron/M/Down`, кликабельное), и **свободный
слот** — пустая ячейка с пунктирной рамкой, куда дизайнер кладёт что угодно.

## Поиск и фильтры

Над шапкой таблицы — строка: `InputSearch` (Size=S, без подписи/hint/лишних
иконок — только лупа+placeholder) слева и кнопка «Фильтры» (`Action Button`,
Neutral/Small/Square, иконка Filter) справа от неё. Есть на всех состояниях
таблицы (по умолчанию, с выделением, скелетон, ошибка, частичная загрузка) —
строка поиска не должна пропадать/появляться в зависимости от состояния данных.

## Состояния и корнер-кейсы

На странице «Table» — примеры side-by-side, каждый подписан настоящей Figma
аннотацией (`node.annotations`), а не текстовым слоем поверх макета:
- По умолчанию · с выделенными строками (+ Group Actions Bar) · загрузка
  (скелетон, 20 строк) · ошибка загрузки (Empty Content) · частичная загрузка
  (часть строк реальные, часть — скелетон) · вложенность (отдельный кейс).

## Вложенность (tree-таблица)

Отдельный кейс, не смешивается с плоскими. Обязательные правила:

- **Триггер раскрытия** — шеврон в первой ячейке ИЛИ вся строка; выбор
  фиксируется один раз и держится одинаковым по всей системе (не смешивать
  варианты между экранами).
- **По умолчанию всё свёрнуто** — раскрывает только пользователь; состояние
  желательно сохранять между сессиями.
- **Глубина ≤ 2–3 уровней.** Для 4+ уровней — drill-down на отдельный экран,
  не дальнейшая инлайн-вложенность.
- **Индикация уровня — тремя средствами одновременно:** отступ слева, кратный
  уровню + лёгкая заливка фона глубже с каждым уровнем + тонкая вертикальная
  направляющая от родителя. Одного отступа недостаточно при глубине > 2.
  Заливка — один и тот же токен `background/secondary-b`, шаг прозрачности
  **5% на уровень** (L1=5%, L2=10%, L3=15%, L4=20%), подобрано и утверждено по
  палитре-пипетке. У каждой новой корневой ветки счётчик уровня и прозрачности
  начинается заново с 5% — не копится по вертикали таблицы.
- **Агрегат в свёрнутой родительской строке** (количество/сумма/статус-роллап)
  — раскрытие должно быть осознанным решением, а не «слепым» кликом.
- **Сортировка** — внутри группы (иерархия сохраняется), не сквозная плоская —
  так корректнее для корпоративных данных.
- **Фильтрация** — родитель виден, если хотя бы один потомок проходит фильтр,
  с индикацией частичного совпадения.
- **Выбор строк — каскадный:** выбор родителя выбирает всех потомков; частичный
  выбор потомков → `Indeterminate` у родителя (кит: `CheckboxSquare`,
  `Type=Indeterminate`).
- **Действия по уровням не смешиваются** — Edit/Skip/Delete и т.п. привязаны к
  конкретному уровню визуально. Для рискованных данных редактируемые поля
  стоит показывать только внутри раскрытой области — это осознанное трение
  против случайных правок.

## Известное ограничение — подтверждение удаления

Кнопка «Удалить» в раскрытых строках (Edit/Skip/Delete) сейчас срабатывает
без подтверждения — синтетический тест респондента застрял именно на этом
(необратимое действие без предупреждения + кнопка стоит вплотную к
«Пропустить»). Осознанно не чиним сейчас: компонент `Confirm` в ките сам ещё
`(In progress)` — см. `components/INDEX.md`. Когда он будет готов — обернуть
«Удалить» в Confirm-попап и увеличить отступ до «Пропустить». Не забыть при
следующей работе над Table.

## Правила применения

- Плотность — S (компактно, по умолчанию для таблиц) или M, как в
  [`cell-2-0.md`](cell-2-0.md).
- Скролл и пагинация — **только для desktop**.
- Групповые операции показывать только при реальном выделении строк.
- Компоненты-атомы берём из библиотеки как есть, руками токены внутри них не
  трогаем (см. общее правило кита).
