## Практика

- **Делай:** структура всегда одна — Заголовок → Описание → контейнер кнопок
  (Secondary слева + Primary справа). Собирается из трёх готовых организмов/атомов,
  без рисования новых примитивов:
  - **Desktop** — контейнер `Popup` (Type=Desktop). У него уже есть встроенные
    свойства `Title Text` / `Desc Text` / `Description` — заголовок и описание
    заводим через них, а не отдельным текстовым блоком.
  - **Mobile** — контейнер `Bottomsheet` (Type=Default), НЕ `Popup` (Type=Mobile).
    См. отдельное предостережение ниже.
  - **Кнопки** — инстанс `Floating Button` (Scroll=No, Buttons View=Horizontal).
    Внутри уже готовая пара `Action Button` (Secondary слева, Primary справа) —
    только переопределяем текст (`Text#6860:0`) и выключаем иконки
    (`Left Icon#1112:241` / `Right Icon#1184:17` = false).
  - **Остров:** склеиваем контейнер заголовка и контейнер кнопок без зазора
    (`itemSpacing=0`) — у `Popup`/`Bottomsheet` радиус уже скруглён только сверху,
    поэтому обёртке достаточно `cornerRadius`+`clipsContent=true`, чтобы получить
    один бесшовный остров, а не две сшитые карточки. На Desktop низ тоже скруглён
    (16), на Mobile низ прямой (0) — это настоящий bottom sheet, а не плавающая
    карточка.
  - **Ширина Desktop параметрическая:** 520 (компактный) / 722 (стандартный) / 900
    (когда в попапе много данных/доп. контента). Задаётся через
    `layoutSizingHorizontal = 'FILL'` на инстансах `Popup` и `Floating Button`
    внутри обёртки нужной ширины — сама библиотека это выдерживает без поломок.
  - **Слот под кастомный контент:** между описанием и кнопками зарезервирован
    пустой `Content Slot` (0 высоты по умолчанию, паддинг по бокам 16 mobile / 24
    desktop) — можно вставить иллюстрацию (например `Dialog`/`Empty` из
    `Life-10_Icons`), список или доп. пояснение; пока пуст — не влияет на вёрстку.
  - **Без кнопок (empty state):** контейнер кнопок можно убрать целиком — тогда
    крестик в шапке `Popup` остаётся единственным способом закрытия.
- **Избегай:**
  - Не используем `Popup` (Type=Mobile) для мобильного Confirm — это generic
    `Toolbar`-компонент без слота под описание, с лишними back/«...»-иконками не по
    контексту попапа (сам компонент помечен «не финализирован»).
  - Не полагайся на `layoutSizingHorizontal = 'FILL'` в одиночку для текста, который
    должен переноситься по строкам — без явного `resize()` на фиксированную ширину
    и `textAutoResize = 'HEIGHT'` FILL схлопывает текстовый узел в нить по одному
    символу на строку (см. `references/gotchas.md` в figma-use).
  - Не оставляй зазор между `Popup`/`Bottomsheet` и `Floating Button` — по дизайну
    у них радиус только сверху, зазор визуально рвёт остров на две карточки.

## Почему

Экономит повторное открытие способа склейки `Popup`/`Bottomsheet` + `Floating
Button` + `Action Button` и грабли с FILL/переносом текста — при первой сборке
на это ушло заметно больше итераций, чем ожидалось. Данных по метрикам нет
(это не A/B), поэтому уверенность ⚪, а не 🟢.

## Когда применимо

- **Работает:** любой сценарий «один вопрос — одно действие» — подтверждение,
  удаление, короткое информационное сообщение (в том числе без кнопок).
- **Не работает:** длинный контент, множество полей ввода — для этого отдельный
  экран (см. `components/popup.md`: «не носит длинный контент»), Confirm в форму
  не растягиваем.
