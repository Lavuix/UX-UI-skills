# Паттерн: один сквозной аудит токенов перед «готово», не по одной категории за раз

| Поле | Значение |
|------|----------|
| Категория | Компоненты / Процесс сборки |
| Уверенность | ⚪ допущение |
| Источник | Сборка компонента Table, сессия 2026-08-13 |
| Обновлено | 2026-08-13 |

## Практика

- **Делай:** прежде чем сказать «готово» по новому/изменённому куску макета —
  прогони **один комбинированный проход** по трём категориям сразу, а не жди,
  пока пользователь укажет на каждую по очереди:
  1. **Отступы** — `paddingLeft/Right/Top/Bottom`, `itemSpacing` каждого
     `layoutMode`-фрейма сверь со шкалой `--space-*` (0,4,8,10,12,16,24,32,40,48,64).
  2. **Радиусы** — `cornerRadius` каждого фрейма сверь со шкалой `--radius-*`
     (0,2,4,8,10,12,16,24,100=round).
  3. **Цвета** — у каждой заливки/обводки: (а) она вообще привязана к переменной
     (`boundVariables.color` не пусто), и (б) это **семантический** токен темы
     (`content/*`, `background/*`, `border/*`, `content/system/*`), а не
     примитив бренда напрямую (`Green/50`, `Orange/55`…) — примитивы напрямую
     запрещены самим tokens.md.
  - **Скоуп прохода:** только узлы, которые сам создал/изменил в этом сеансе.
    Спускаться внутрь инстансов ради поиска СВОЕГО контента (слоты) — можно и
    нужно; трогать сам факт покраски/отступов **внутри чужого кит-компонента**
    (Tag, Userpic, CheckboxSquare, Scroll…) — нельзя, это не твоя зона.
  - **Механика прохода** (рабочий скрипт из этой сессии, можно переиспользовать
    как основу): рекурсивный `walk()` по дереву без блокировки по `type ===
    'INSTANCE'` (иначе пропустишь свой же контент внутри слота — отдельная
    ловушка, см. ниже), с проверкой каждого узла на все три категории сразу,
    а не тремя отдельными проходами.
- **Избегай:**
  - Чинить только ту категорию, на которую указал пользователь, и останавливаться.
    В этой сессии так было трижды подряд: почистил цвета — пользователь нашёл
    отступы; почистил отступы — нашёл радиусы; почистил радиусы — нашёл ещё
    цвета (примитивы вместо семантики). Один сквозной проход сразу по всем трём
    категориям убирает большинство таких кругов.
  - Блокировать спуск в `INSTANCE`-узлы при обходе. Компонент типа `Table Cell`
    сам является инстансом — весь твой контент (точки статуса, текст дельты,
    плейсхолдеры) физически лежит **внутри** него. Ранний `return` на
    `type==='INSTANCE'` пропускает именно то, что нужно проверить.

## Почему

Каждый частичный проход экономит время в моменте, но заставляет пользователя
находить следующую категорию самому и заново объяснять «и это тоже на
токенах». Три раунда за одну сборку — сигнал, что дешевле сразу прогнать все
три проверки вместе, чем чинить их последовательно по одной. Данных/метрик
нет, это вывод по итогам одной сессии — уверенность ⚪.

## Когда применимо

- **Работает:** любая новая сборка/правка компонента в Figma-ките перед тем,
  как показать результат готовым.
- **Не работает** (не пытайся туда же впихнуть): аудит типографики — она уже
  идёт отдельным, более простым проходом (сверка `fontSize`+`fontName` →
  замена на `textStyleId`), не смешивай с этим тройным проходом — категории
  разной природы, разная механика замены.

## Пример

Три прохода из сессии 2026-08-13 над Table: `padding` (нашёл 6+3 нарушения
в тулбарах/скролл-строках), `cornerRadius` (42 плейсхолдера слота на `6` вместо
`8`), цвет (476+42 первичных исправления, потом ещё 52 на семантику
`content/system/*` вместо Brand-примитивов).
