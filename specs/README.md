# specs/ — входные спеки для оркестра

Файлы отсюда скармливаются агентам командой:

```
/feature specs/<имя-файла>.md
```

Спека — это **вход**, который пишешь ты. Всё остальное оркестр генерирует сам:
паспорт проекта (`PROJECT.md`) собирает Scout, правила «мозга» (`brain/`) —
Chronicler после твоих правок. Поэтому здесь только спеки, а не сгенерированные
артефакты — их подделывать нельзя, иначе конфликт с тем, что создают агенты.

## Файлы

- `_TEMPLATE-spec.md` — пустой шаблон. Копируй под каждую новую фичу.
- `EXAMPLE-onboarding-2-steps.md` — заполненный пример (из нашей гипотезы H-000).

## Как разделы ложатся на агентов

| Раздел спеки | Какой агент это ест |
|--------------|---------------------|
| §1 Гипотеза, §2 Проблема | Spec Analyst — план + гейты, ловит дыры |
| §4 Пользователи, §6 Требования | UX Advisor — обоснование против прецедентов |
| §5 Экраны и состояния | Builder — собирает каждое состояние из библиотеки |
| §7 Спорные решения | Respondent — слепой A/B на синтетической панели |
| Метрики + acceptance criteria | гейты ревью и метрика обучения Chronicler |

## Совет из FAQ репозитория

Делай `/feature` **первой** командой сессии, без сопроводительного текста —
иначе какой-нибудь Figma-плагин может перехватить запрос.
